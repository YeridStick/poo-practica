Mono<T> — 0 o 1 item

Mono es un Publisher que emite como máximo un elemento y luego completa (o emite error). Equivale a un Optional reactivo.

Mono.just("Hola WebFlux") .map(String::toUpperCase) .subscribe(System.out::println); // Con creación diferida Mono.fromSupplier(() -> calcularPrecio()) .doOnSuccess(p -> log("precio: " + p)) .subscribe();

Flux<T> — 0..N items

Flux es un Publisher que emite múltiples elementos. Es el equivalente reactivo de una lista o stream.

Flux.just(1, 2, 3, 4, 5) .filter(n -> n % 2 == 0) .map(n -> n * 10) .subscribe(System.out::println); Flux.range(1, 100) .take(5) .collectList() .subscribe(System.out::println);

flatMap vs concatMap vs switchMap

flatMap → concurrente, no garantiza orden. concatMap → secuencial, mantiene orden. switchMap → cancela la anterior al llegar nueva señal.

// flatMap: concurrente Flux.just("a","b","c") .flatMap(s -> llamadaAsync(s)) .subscribe(); // concatMap: orden garantizado Flux.just("a","b","c") .concatMap(s -> llamadaAsync(s)) .subscribe();

Operadores clave

Los operadores transforman el stream sin suscribirse. Son lazy: nada ocurre hasta que alguien se suscribe.

flux.map() // transforma 1:1 flux.flatMap() // transforma 1:N asíncrono flux.filter() // filtra según predicado flux.reduce() // acumula en un Mono flux.collectList() // Flux -> Mono<List> flux.zip() // combina dos Flux flux.merge() // une Flux concurrentes flux.take(n) // tomar N elementos flux.timeout() // falla si tarda mucho flux.retry(n) // reintentar N veces

Manejo de Errores

A diferencia del try-catch imperativo, los errores son señales en el stream y se manejan con operadores.

Mono.just(0) .map(n -> 10 / n) // ArithmeticException .onErrorReturn(-1) // valor por defecto Flux.error(new RuntimeException("fallo")) .onErrorResume(e -> Flux.just("fallback")) flux.doOnError(e -> log.error("Error:", e)) .retry(3) .timeout(Duration.ofSeconds(5))

Schedulers & Hilos

Reactive es single-thread by default. Los Schedulers controlan en qué hilo se ejecuta cada parte del pipeline.

Flux.just(1,2,3) .subscribeOn(Schedulers.boundedElastic()) // hilo suscripción .publishOn(Schedulers.parallel()) // hilo publicación .subscribe(); // Para I/O bloqueante (JPA, calls HTTP síncronas): Mono.fromCallable(() -> repoBlocking.save(entity)) .subscribeOn(Schedulers.boundedElastic())
