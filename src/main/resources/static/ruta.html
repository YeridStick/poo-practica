El Cambio de Paradigma Reactivo

Infografía: Del flujo secuencial bloqueante al Event Loop no bloqueante.

La programación reactiva no es solo una librería, es un cambio de mentalidad. Pasamos de un modelo donde el hilo espera por la respuesta (Bloqueo) a uno donde el hilo se libera inmediatamente y reacciona cuando los datos están listos.

¿Cuándo se genera un bloqueo?

En el modelo tradicional, operaciones como consultas a DB, llamadas a APIs o lectura de archivos detienen el hilo de ejecución por completo.

Context Shift

Cambiar entre hilos bloqueados es costoso para la CPU. WebFlux optimiza esto usando pocos hilos (Event Loop) que nunca se detienen.

Diferencia de Rendimiento: Ejercicio de Latencia

Simulación de 3 tareas con latencia de 1s 
public void procesoImperativo() {
    List<String> datos = List.of("Tarea 1", "Tarea 2", "Tarea 3");
    for (String dato : datos) {
        try {
            Thread.sleep(1000); // Bloqueo total del hilo
            System.out.println("Procesado: " + dato);
        } catch (InterruptedException e) { ... }
    }
    System.out.println("Fin"); // ¡Sale después de 3 SEGUNDOS!
}
Resultado: Tiempo total ≈ 3s. El hilo estuvo "dormido" y desperdiciado la mayor parte del tiempo.
public void procesoReactivo() {
    Flux.just("Tarea 1", "Tarea 2", "Tarea 3")
        .delayElements(Duration.ofSeconds(1)) // Latencia no bloqueante
        .doOnNext(dato -> System.out.println("Procesado: " + dato))
        .subscribe();
    
    System.out.println("Fin del hilo principal"); // ¡Sale INMEDIATAMENTE!
}
Ventaja: El hilo principal se libera al instante para atender otras 10,000 peticiones mientras Reactor gestiona la espera de fondo.

Optimización de hilos Event Loop para manejar miles de conexiones con mínima RAM.

Operadores Maestros: Reactor Core

Transformación y Filtrado

flux.filter(n -> n > 10)
    .map(n -> "ID: " + n)
    .flatMap(id -> service.call(id))

Combinación y Resiliencia

Flux.zip(flux1, flux2)
    .retryWhen(Retry.fixedDelay(3, Duration.ofSeconds(2)))
    .onErrorReturn("Error final");

zip combina flujos. retryWhen permite reintentar peticiones fallidas automáticamente.
